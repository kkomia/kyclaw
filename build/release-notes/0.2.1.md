kyclaw 0.2.1

本次更新内容：

0.2.1 是 **0.2.0 的缺陷修复版**：不引入新功能，内核与路由面与 0.2.0 相同（DSH Node 子进程、`@deepseek-ai/*` **v0.2.1-rc.2**；0.2.0 主动下架的 8 条宿主 API 维持 501，计划 0.2.x 恢复）。本版集中修 0.2.0 发布后确认的四个残留问题，更正 0.2.0 发行说明里已过期 / 不成立的表述（PB-052），并新增一项**卸载时可选删除本地历史数据**的安装器改进（不涉及内核与运行时路由面）。

修复

- **代码块首帧空白（PB-042 / R16）**：代码块**第一次出现在界面上时就带 Shiki 高亮结构**，不再「先挂空壳或纯文本、随后再换成高亮」；流式过程中围栏刚打开、代码正文还没到的空代码块不再先落 DOM。修法是渲染前同步取高亮（高亮器就绪后 `codeToHtml` 本就是同步的，并保留模块级结果缓存）；高亮器尚未就绪的极短窗口不挂空壳，就绪后一次成型。**R16 判据没有放宽**：`firstHtml=''` 仍是红；语言未打包或高亮失败时仍按纯文本显示，正文不丢（这两条本来就没有 Shiki 结构，不属于「首帧空白」）。
- **流式回复中内核崩溃的错误卡文案（PB-050 / S6）**：0.2.0 在「慢速流式回复进行中内核进程被杀」时，错误卡偶发退化成通用「服务暂时不可用 / 连接中断：请检查网络或本地服务后重试。」，拿不到退出码与日志路径。本版把连接层断裂后的失败**按内核退出事实归类**（给子进程 `exit` 事件一个有限宽限，避免 socket 的 `read ECONNRESET` 先到就当成网络错误）：内核已退出 → 卡片显示「内核进程已退出（exitCode=…）」、`kernel.crashed` 记录的 signal/时间、日志绝对路径与「重启应用」建议；内核没退出 → 仍按普通连接错误显示「连接中断」，不把网络故障误报成内核崩溃。
- **每次启动多 1 个空会话（PB-051）**：0.2.0 每次启动都会新建一个 ≤1KB 的空白会话（本地会话数据每次启动 +1，长期使用持续累积）。本版修掉启动路径上创建空白会话的来源，**每次启动不再新增空会话**；`defaultSessionId` / 空白会话过滤与冷启动读史行为不回退（历史已产生的空会话不自动清理，见「已知问题 / 边界」）。
- **下架的会话↔项目映射不再假报「项目加载失败」（PB-053）**：0.2.0 把 `/api/projects/mappings` 下架为 501 `feature-disabled`，但界面仍无条件加载映射、把 501 当普通失败，侧栏固定显示「项目加载失败 + 重试」（每次启动都出现、重试永远失败，全新 profile 同样复现）。本版把「主动下架」识别为独立状态（`FeatureDisabledError`，不靠比对文案）：501 不落错误、不再重试；依赖旧项目映射的入口统一隐藏或中性化；旧项目数据不迁移、不兼容（0.2.0 已决定舍弃），项目能力留待后续版本重做。
- **同类下架功能的界面中性化（PB-053 泛化）**：同一原则推广到 0.2.0 主动下架的其它能力——界面不再把 501 当「加载失败」显示红字 + 重试（重试永远不会成功），改为中性说明「本版暂不可用（0.2.x 恢复）」或直接不显示依赖该能力的入口。覆盖：① 首页热力图（`/api/usage/calendar` 501）→ 中性说明，不再显示「本地活动读取失败 + 重试」；② 用量页（设置→用量 / `#/usage`，`/api/usage` 501）→ 中性「本版暂不可用」，不再红字错误 + 重试；③ 记忆页 / 记忆空间（`/api/memory` 501）→ 中性「本版暂不可用」，不再红字 + 重试；④ 轨迹页的三条软腿（用量 / 请求快照 / 任务历史）在 501 时静默降级，不再显示「未取到」「任务历史加载失败」一类提示或重试；⑤ 侧栏项目区、选择项目胶囊、会话菜单「移至项目」、「记忆」栏项目记忆指令块、归档页项目分区在项目映射 501 时整块隐藏（PB-053）。
- **统一下架文案（PB-052 同类过期措辞）**：`FEATURE_DISABLED_MESSAGE` 从「0.2.0 暂不可用（0.2.x 恢复）」改为「本版暂不可用（0.2.x 恢复）」——0.2.1 是本版，旧措辞会指向错误版本。

卸载增强（安装器）

- **卸载时可勾选「同时删除本地历史数据」**：卸载向导新增一个勾选框（**默认勾选**）。勾选后随卸载一并删除：
  `%APPDATA%\kyclaw`（会话记录、内核 `dsh-home`、设置、加密密钥、日志、模型缓存、旧版 `kyclaw.db`）与
  `%LOCALAPPDATA%\kyclaw-updater`（更新下载缓存）。取消勾选则保留这些数据，重装后还能用回会话与密钥。
- **不会删除用户工作区里的文件**：默认工作区（例如 `%USERPROFILE%\kyclaw\工作区`）不在删除范围内——那里可能有你自己的文件。
- **自动更新 / 静默卸载默认保留数据**：升级流程调起的卸载器一律不删；无人值守卸载需要显式传 `--delete-app-data` 才会删。
- 真机点按验收在发版安装包上执行（开发机不做真实卸载：会真删 `%APPDATA%\kyclaw` 并改本机注册表）。

已知问题 / 边界

- **路由面与内核不在本版范围**：0.2.0 主动下架的 8 条宿主 API（tasks / goal / projects / ppt / mcp / memory / usage / trajectory，均返回 501）**仍不可用**，计划 0.2.x 恢复；本版只改界面表现（不再假报「加载失败」），不代表能力恢复。
- **0.2.0「已知问题 / 边界」的其余条目仍然适用**（完整清单见 0.2.0 发行说明）：R09 用量统计 / 库值对账尚未恢复（页面中性显示「本版暂不可用」，0.2.x 恢复）、writer-held 只读合同未复现、PB-014 极短流跳帧、跨重启归档集合不自动加载、cwdOf 只保证默认工作区、`kept` 恒 null、暂无「取消归档」入口、B3.6 与子 agent 不承诺、PB-036 插件技能描述、PB-045 Windows ACL 环境问题等。
- **旧项目数据不迁移、不兼容**：0.2.0 下架的会话↔项目映射历史数据直接舍弃；settings 里的旧 `projects` 字段保留但产品不再读取；项目能力留待后续版本重做。
- **本版修复带来的取舍/边界**：
  - PB-042：高亮器首次加载完成前的极短窗口内，首条代码块**不先挂空壳/纯文本**（最多晚一个高亮器加载周期；模块加载即预热，正常为 0）；流式中「围栏已开、正文未到」的空代码块不再上屏；语言未打包或高亮失败仍按纯文本显示，正文不丢（这两种本来就没有 Shiki 结构）。
  - PB-050：in-flight 内核崩溃卡的主按钮仍是「再跑一次」；极窄竞态（kill 恰撞 `session/prompt` RPC 建立、`session/follow` 等待中、或 child `exit` 晚于 1.5 秒宽限）仍可能落到通用/超时文案，不在本版证据场景内。
  - PB-051：升级/新 profile 的**首次**启动会建 1 个隐藏默认会话锚点（~330B + 1 条 projcache，`kyclaw-default-*` 稳定 id），此后每次启动 0 增长；换工作区会为新 cwd 建 1 个锚点（每工作区 1 个）；**历史已产生的旧空会话不自动清理**（不擅删内核 home 持久文件；侧栏 blank/default 双过滤本就不可见）。
  - PB-053：本版只把下架功能的界面表现改为中性，**不代表能力恢复**；旧项目数据不做迁移/兼容。
