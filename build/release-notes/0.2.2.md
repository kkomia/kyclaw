kyclaw 0.2.2

本次更新内容：

0.2.2 是 0.2.1 的**缺陷修复版**：修掉 0.2.0 / 0.2.1 发布后实测确认的两个问题——① 设置里配好模型、连接测试也显示成功，但一发消息就报「模型密钥缺失或失效」；② 侧栏「项目」区连同「+ 新建空白项目 / 使用现有文件夹」入口一起消失，只剩「任务」。内核与路由面与 0.2.1 相同（DSH Node 子进程、`@deepseek-ai/*` **v0.2.1-rc.2**；0.2.0 主动下架的 8 条宿主 API 维持 501，计划 0.2.x 恢复）。

修复

- **配了模型却发不出消息（P0）**：根因是 0.2.x 把对话迁移到 DSH 内核之后，内核只认**它自己**的模型配置（`llm-deepseek` / `llm-pi-ai` 路由、内核 credential store、`agent-default-model`），而 kyclaw 设置页写的是自己的 `settings.json` + safeStorage 密钥——两者在 0.2.0 / 0.2.1 从未接起来。所以「测试连接成功」跑的是 kyclaw 自己的探测链，真发消息时内核找不到凭证，回 `MISSING_CREDENTIAL`，界面映射成「模型密钥缺失或失效」。
  本版新增**模型桥**（主进程把 kyclaw 的 provider + 密钥同步进内核的活配置）：
  - **DeepSeek 官方端点** → 用内核自带的 `deepseek-official` 路由：端点自动指到 Messages 地址（`https://api.deepseek.com/anthropic`），密钥写入内核 credential store 的 `DEEPSEEK_API_KEY`；
  - **其它 OpenAI 兼容 / Anthropic 端点** → 在内核 `llm-pi-ai` 里建一条 `kyclaw-<通道id>` 自定义路由（协议按通道类型选 `openai-completions` / `anthropic-messages`，模型清单按设置里的列表带上下文窗口/图片模态等实测元数据），密钥写内核凭证；
  - 同时把内核默认模型指到「当前选中的通道 + 模型」。在设置里改 provider / 写密钥 / 删 provider，或在输入框下方切模型，都会**即时重新同步**（不用重启应用）；
  - 没配 provider（或官方端点缺密钥）时**不动**内核配置，保持原样，不会把上一次能用的配置改坏。
- **侧栏「项目」区恢复（0.2.1 的回归）**：0.2.1 为了让 501 下架的旧项目映射不再假报「项目加载失败」，把整个项目区隐藏了，连「+ 新建空白项目 / 使用现有文件夹 / 管理工作区」入口也一起没了。本版恢复项目区，并把会话归属改成**按内核会话自己的工作目录（cwd）推导**（不再依赖已下架的映射 API）：会话落在哪个项目目录下就归到哪个项目（嵌套项目取最具体的那个）。组头、管理菜单、空态、项目行 ⊕ 全部回来；501 下仍不出现红字「项目加载失败 / 重试」。
  - 项目行 ⊕ / 新建项目后开会话：新会话会**建在该项目目录里**（内核 session 的 cwd = 项目路径），不再落到默认工作区；
  - 已归档项目仍按原口径隐藏；删掉项目后，它名下的旧会话回到「任务」组，内容不受影响（内核里仍在原目录）。

已知问题 / 边界

- **8 条宿主 API 仍下架**（tasks / goal / projects / mcp / memory / usage / trajectory 均返回 501），计划 0.2.x 恢复。本版只恢复「项目区」的展示与新建（不依赖映射 API）；**写映射**的入口（会话菜单「移至项目」、选择项目胶囊、归档页项目分区）仍隐藏。
- **旧项目映射数据不迁移、不兼容**：项目归属以会话实际工作目录为准；同名/重叠目录按「路径最长 = 最具体项目」归组。
- **模型桥只桥「当前默认通道」**：同一时刻只有一条通道被送进内核（切模型/通道会即时重同步）。kyclaw 侧的「思考强度」「上下文长度」两个偏好暂未透传给内核（内核按自己的默认走）；内核侧的模型清单与 kyclaw 设置页各自独立展示，以「当前选中模型」为准。
- **密钥会同时存在两处**：kyclaw 自己的 safeStorage 密文 + 内核 credential store（`$DSH_HOME/.credentials.yaml`，与 DSH 桌面端同一套的本机明文文件）。两处都由本机应用数据目录管理，随「卸载时删除本地历史数据」一起清理。
- 0.2.1「已知问题 / 边界」中与内核 / 路由面相关的条目仍然适用（writer-held 只读合同未复现、PB-014 极短流跳帧、跨重启归档集合不自动加载、cwdOf 只保证已知会话、`kept` 恒 null、B3.6 与子 agent 不承诺、PB-036 插件技能描述、PB-045 Windows ACL 环境问题等）。
