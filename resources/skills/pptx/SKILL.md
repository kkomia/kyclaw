# pptx：用 `create_ppt` 做演示文稿、用 `edit_ppt` 改它

## 什么时候用我

- 用户要"一页页讲给别人看"的东西：汇报、路演、答辩、培训、产品介绍、周报演示。
- 用户明确说 `.pptx` / PowerPoint / 幻灯片 / PPT。

不要用我：连续阅读的长文（→ `docx` 技能）、以数据表为主体（→ `xlsx`）、要打印或外发的成品文档（→ `pdf` 技能）。

## 一次调用的形状

```
create_ppt({
  title: "2026 年度产品规划",        // 会自动生成一张封面
  subtitle: "产品部 · 2026-01",       // 只在封面出现
  theme: "商务蓝",                    // 可选；不填就用用户固定的模板，用户也没固定就按内容自动配
  slides: [                          // 1-60 页，按顺序排在封面之后
    { section: "现状" },                                    // 章节页（自动带序号）
    { title: "用户规模", bullets: ["月活 128 万", "留存 42%"] },  // 正文要点页
    { title: "关键指标", stats: [{ value: "128 万", label: "月活" }, { value: "42%", label: "次月留存" }] },
    { title: "成本对比", table: { headers: ["项目", "去年", "今年"], rows: [["服务器", "80 万", "62 万"]] } },
    { title: "该做什么", columns: [{ title: "要做", bullets: ["自研引擎"] }, { title: "不做", bullets: ["多端"] }] },
    { quote: { text: "把复杂留给自己，把简单留给用户", source: "—— 团队共识" } }
  ],
  path: "演示/年度规划.pptx"        // 可选：不给就按 title 派生文件名，落在当前会话工作区
})
```

回执形如：`已创建 …/演示/年度规划.pptx（84213 字节，12 页演示文稿，模板「商务蓝」）`。

## 改的时候：`edit_ppt`（只发改动，不发整份）

**第一版用 `create_ppt`；只要不是"重做"，改动一律走 `edit_ppt`** —— 它只收"改哪一页 + 改什么"，
其余页面从会话里记着的源结构读，不必再发一遍。钱花在模型输出上：发一个 op 和重发整份
`slides` 是两种量级的开销。

```
edit_ppt({
  path: "演示/年度规划.pptx",        // 必填：create_ppt 回执里那个路径
  ops: [
    { op: "replace", page: 3, slide: { title: "用户规模", bullets: ["月活 128 万", "次月留存 45%"] } },  // 换掉第 3 页
    { op: "insert",  after: 4, slide: { title: "风险", bullets: ["上游涨价（工信部）"] } },              // 第 4 页后插一页
    { op: "delete",  page: 7 },                                                                        // 删掉第 7 页
    { op: "meta",    title: "2026 年度产品规划（修订）" }                                                // 改封面这类单字段
  ]
})
```

- **页号是 PowerPoint 的页号**（1 起、**含封面**）：第 1 页是封面 —— 封面不能 replace / delete，
  改它用 `meta`（`title` / `subtitle` / `theme`）。
- `ops` 按顺序应用，每一步都按**当前**页序算（"在第 2 页之后插一页"之后再"删第 4 页"，删掉的正是
  刚插进来的那一页）。
- 回执与 `create_ppt` 同形，末尾多一段**改后页序**（`1 封面〈…〉｜2 要点〈…〉…`）——
  就用它核"用户说的第 3 页"是哪一页，别为此再 `render_ppt` 一遍。
- 替换/插入的新页**必须排得出版式**（`title` / `bullets` / `stats` / `table` / `columns` / `quote` /
  `section` 至少给一个），否则整次调用会被拦下：宁可报错，也不能让某一页悄悄消失。
- 盘上那份**被手动改过或删掉了**时它不会动手：回执里让你选 `ifChanged` ——
  `overwrite`（以源为准覆盖）/ `adopt`（以文件里的文字为准重建源，版式会按内容重排）。先问用户再选。

## 版式怎么选（八种，`layout` 可省）

| 页面类型              | 给的字段                                | 不填 `layout` 时       |
| --------------------- | --------------------------------------- | ---------------------- |
| 封面                  | （自动从 `title` / `subtitle` 生成）    | —                      |
| `section` 章节页      | `section`（自动带序号）                 | 给了 `section` 就是它  |
| `content` 正文要点    | `title` + `bullets`                     | 最常用的默认           |
| `stats` 数字卡片      | `title` + `stats`                       | 给了 `stats` 就是它    |
| `table` 表格          | `title` + `table`                       | 给了 `table` 就是它    |
| `two-column` 左右分栏 | `title` + `columns`（**必须正好两栏**） | 给了 `columns` 就是它  |
| `quote` 引言          | `quote.text`（+ 可选 `source`）         | 给了 `quote` 就是它    |
| `closing` 结尾页      | `title`（写结论 / 下一步这类有内容的）  | 想给结尾页就自己写一张 |

显式给的 `layout` 撑不起那一页（比如 `layout: "stats"` 却没给 `stats`）时，会退到按内容自动挑；什么都挑不出来就跳过这页。

## 主题（`theme`）的十个取值

极简黑白 / 商务蓝 / 科技暗 / 暖橙 / 墨绿 / 紫罗兰 / 学术紫 / 酒红 / 湖蓝 / 奶油。

- **默认不要指定 `theme`**：用户在对话页的「PPT」胶囊里固定的那套优先，没固定则按标题自动配（同一份内容每次配到同一套）。
- 只有用户明确要求换风格时才写：方案/汇报 → 商务蓝、湖蓝；技术发布 → 科技暗；学术答辩 → 学术紫、墨绿；财报数据 → 酒红；活动创意 → 暖橙、奶油、紫罗兰；克制 → 极简黑白。

## 页面类型与视觉层级

一份成型的演示文稿由五个**功能位**构成：封面 / 目录 / 章节 / 内容 / 结尾。八种 `layout` 已经覆盖它们，
你要做的是**把每一页归到一个功能位**，而不是让整份都是"标题 + 要点"。

| 功能位   | 用哪个 layout                                  | 这一页只放什么                  |
| -------- | ---------------------------------------------- | ------------------------------- |
| 封面     | 自动（从 `title` / `subtitle` 生成）           | 标题 + 副标题 + 一个视觉重心    |
| 目录     | `content`（`bullets` 写 "01 现状" "02 做法"…） | 3-6 个章节，序号写法统一        |
| 章节分隔 | `section`                                      | 序号 + 章标题（+ 可选一句引导） |
| 内容     | `content` / `stats` / `table` / `two-column`   | 见下：按内容子类型挑            |
| 结尾     | `closing`                                      | 结论、下一步、要对方做的决定    |

**内容页的子类型**决定用哪个 layout：文字要点 → `content`；关键数字 → `stats`；数据表 → `table`；
两方对比 → `two-column`；一句立场 → `quote`；时间线/流程 → 用 `content` 的短条目按顺序写。

### 字号层级（判断信息主次用，不是参数）

> **可选口味（默认打法）**：这一节讲的是"做成什么样更好看"，只是**默认打法**，不是硬口径。
> **用户明确要求别的风格时以用户为准**（比如"字号拉近些""全都放大"），别拿这张表去驳回用户。

模板已把字号定死，你不必也不能改。列出来是让你判断"这段内容够不够格占一页"：

| 位置        | 字号量级 | 关系                         |
| ----------- | -------- | ---------------------------- |
| 封面主标题  | 最大     | 至少是副标题的 2-3 倍        |
| 章节序号    | 很大     | 比章标题更抢眼               |
| 页标题      | 中       | 与正文拉开 ≥2 倍差距         |
| 正文要点    | 基准     | 一条一行                     |
| 数字卡数值  | 很大     | `stats.value` 是这一页的主角 |
| 页脚 / 注释 | 最小     | 不要在这里放观点             |

**相邻两级的字号不能接近**：差不到 1.5 倍就会"看起来一样大"，层级就读不出来。这也是为什么
`stats.value` 要写"12%"、"3.2 亿"这种一眼可读的短值，而不是一整个句子。

### 设计原则（八条）

> **可选口味（默认打法）**：下面这八条是"成品长什么样"的**默认打法**，不是硬口径 ——
> **用户明确要求别的风格时以用户为准**（要更满、更花、居中排版、同一个版式连排，用户说了算）。
> **例外：第 7 条是硬口径**（单位进表头），它不属于口味，任何风格下都得守。

1. **一页一个意思**：一页只有一个论点，多了就拆页。
2. **正文左对齐**：要点与段落左对齐；只有封面标题、章节页、结尾页可以居中。
3. **每页至少一个非文字元素**：数字卡、表格、分栏、引言都算；别出现"标题 + 一串字"的光板页。
4. **版式不要连着重复**：连续两页同一种 layout 会显得像没排版过；要点、数字、表格交替着来。
5. **留白 ≥30%**：宁可少写两条，也不要把版面填满。
6. **一套配色贯穿全场**：`theme` 只在开头选一次，中途不换；渐变与动画工具也不做。
7. **数字要带口径**（**硬口径，不属于上面的口味**）：表格里把单位写进表头（"金额（万元）"），
   不要在单元格里重复写单位。
8. **结构要完整**：开场 → 章节 → 要点/数据 → 结论/下一步 → 结尾；缺一段就像半成品。

## 长度上界（超了整次调用会失败，别赌）

| 位置                    | 上界                                    |
| ----------------------- | --------------------------------------- |
| `title` / 每页 `title`  | 200 字                                  |
| `subtitle`              | 120 字                                  |
| `section`               | 80 字                                   |
| `bullets`               | 每页 30 条，每条 500 字                 |
| `stats`                 | 每页 6 张；`value` 24 字、`label` 60 字 |
| `table`                 | 每页 20 行 × 8 列，单元格 200 字        |
| `quote.text` / `source` | 300 字 / 120 字                         |
| `columns`               | 正好 2 栏，每栏 12 条要点               |
| `slides`                | 60 页                                   |

上界 ≠ 合适。**一页一个意思**：要点页 3-6 条、每条 15-25 字最像成品；条数多就拆页，别硬塞。
（这条是**口味**：上界是硬的，但"几条算合适"用户要求更满就以用户为准。）

## 常见坑

- 一页塞满：把整段正文贴进 `bullets`。幻灯片是提醒，不是文档；长句拆成短句或拆页。
- 想用封面页做内容页：封面只认 `subtitle`，内容要点请给 `bullets`（自动走 `content`）。
- `columns` 给一栏或三栏：schema 会直接拒（正好两栏）。
- 表格列数不一致：每一行 `rows[i]` 的长度要对齐 `headers`。
- 把整个文档压成一页：先列出一级提纲，每节一章（`section`）+ 1-3 页要点。
- 数字卡写成句子：`stats.value` 给"12%"、"3.2 亿"这种一眼能读的量。
- 不要在正文里手写"第 3 页"：除封面外每页页脚已自动带「文档标题 + 页码」。
- 连续几页都排要点：读者第三页就疲劳了；中间插入数字卡（`stats`）、表格（`table`）或章节页（`section`）。
- 全篇居中：正文与要点居中很难读，只有封面、章节页、结尾页该居中。
- 每页都是"标题 + 要点"：整份看下来没有视觉锚点；关键结论用 `stats` 抬成数字。
- 一份里换了两套风格：`theme` 中途换会让读者以为换了一份文档，定一次用到底。

## 自检分档：这一档**要看图**

演示文稿是版式密集的产出物 —— 文字自检查不出"文字溢出卡片、错位、对比度不够、整页空话"。
所以 pptx 这一档要求视觉检查：**本部署能渲染时，没看过页图就不算做完**。本机现在能不能渲染，
看 `use_skill` 加载这份手册时拼在**末尾**的「本部署事实」；不能渲染时按下面第 5 条退到文字档，
并且在交付时说清"没做视觉检查"。

## 交付前的硬流程

（"看过才算做完"那条通用纪律在系统指令里；这一节只写 pptx 这一档具体怎么做。）

1. `create_ppt` 之后调 `render_ppt({ path })`：它把每一页渲染成图**直接给你看**，
   同时回一份逐页文字（核对措辞、空值、来源用）。两条省钱的硬口径：
   - **同一份没改动过的 pptx 不要重复渲染**：页图一次就够，重复导出除了再花一遍钱没有任何新信息；
   - 页图落在 `<文件名>_页图/`，**每次渲染都先清空重建**，它只代表**最近一次**的结果。
     `edit_ppt` 是**就地改**（同一个 path 被覆盖）：要把改前那一版留着手动对比，先复制一份
     （`bash` 里 `cp 年度规划.pptx 年度规划-v1.pptx`）再去改。
2. **逐页看**，按五条判：① 有没有哪一页**换一份 PPT 也照样成立**（套话）；② 有没有"没排过版"
   的页（标题 + 一串字、大片空白、文字挤爆）；③ 数字有没有口径（单位、截至时间）；④ 有没有
   连着两三页同一种版式；⑤ 标题像不像标题（与正文拉开差距了吗）。
3. **不合格就回工具改**：改哪几页就发哪几页的 `edit_ppt`（**一次把要改的都列进 `ops`**），
   改完**再 `render_ppt` 一次**确认 —— 改过了才重渲。**不要**为了改一处重发整份 `create_ppt`。
4. 一次最多附 12 页；页数多就分批 `render_ppt({ path, pages: [...] })` 看，别把后几页跳过去。
5. **渲染不可用（或页图没附上来）**：`render_ppt` 只会回**逐页文字结构**，那就把文字逐页核一遍
   （措辞、占位值、来源、页数、结构），并在交付时写明「**只做了结构与内容校验，未做视觉检查**」。
   这一档到此为止：**不要**去找系统的 LibreOffice / `soffice`、不要 `npx`、不要装渲染器、
   不要为此换一个模型 —— 本部署就 `render_ppt` 这一条路，绕道只会白花时间和钱。

**改的时候一次改全。** 要改的几处**一次列进 `ops`**（按顺序应用），别"改一处、渲一次、又发现一处、
再渲一次"——那是这一档最贵的浪费。也别拿 `create_ppt` 重发整份：那是"重做"，不是"改"。

**结构自检通过 ≠ 排版没问题。** 逐页文字（页数、抽取、字段齐）只证明文字与结构没问题；
文字溢出、对齐错位、对比度不够、跨端打开长得一样，**都不在它证明的范围里**。

### 这几类页是被禁的

- **只有致谢的结尾页**（"谢谢观看""感谢聆听"）：它不传递任何信息。结尾页放**结论 / 下一步 /
  要对方做的决定**（用 `closing` 版式，`title` 就写这些）。**想要结尾页就自己写一张有内容的**：
  工具**不再自动补**「谢谢观看」那种占位页了 —— 页面以你给的为准，没给就没有；也别自己写一张
  空话页去凑数。
- **放哪儿都成立的套话**（"信息每天都在变，掌握资讯就掌握先机"）：`quote` 版式只用来放**有出处、
  有立场**的真话（一句能撑住一页的判断），不用来凑页数。
- **只有标题没有内容的页**、**重复的目录页**。
- **页数不够就用内容补，不许用套话凑**：宁可 4 页实在的，也不要 6 页里躺着 2 页空的。

### 每条事实性内容都要带来源

- 数字、政策、事件、引述**逐条**在条目末尾括注来源：`（财政部）`、`（新华社 10-13）`、
  `（中国汽车工业协会）`。
- 检索里找不到出处的说法：**要么删掉，要么写明存疑**（`（未找到公开来源）`），不许当事实写。
- 封面或结尾放一行总来源：`资料来源：新华社、财政部官网（2026-10-13 检索）`。
- 写法统一：机构名为主，需要时补日期；不写"网传""据了解""据悉"。

### 缺值不许写占位符

拿不到的值**不许**写成 `—`、`-`、`待定`、`暂无`、`N/A`。要么补齐（再查一次 / 换一个查得到的
口径），要么**把这一项删掉**。一页里出现一个 `—`，读者就开始怀疑整份数据。

数字要带口径：`（数据截至 2026-10-13 收盘）` 写在**该页第一条要点或表格表头**里 —— 我们的模板
没有页脚注释位，别指望它自己出现。

## 呈现口径（用现有字段能做到的写法）

`create_ppt`（以及 `edit_ppt` 每页内容）的字段只有这些：`title` / `subtitle` / `section` / `bullets` / `stats[{value,label}]` /
`table{headers,rows}` / `columns[{title,bullets}]`（**正好两栏**）/ `quote{text,source}`。
没有坐标、没有自由文本框、没有图片位、没有自定义页脚、没有左右混排版式。
下面两条能用现有字段做出来；做不出来的**不要凭空要求**。

### 「小标题｜正文」的条目写法（推荐）

一条要点写成 `小标题｜正文`，全角竖线分隔：

- `出口退税｜2026 年 4 月起退税率由 13% 降至 9%（税务总局）`
- `货币政策｜PSL 利率下调 0.25 个百分点（央行）`

比一整句平铺的长句好读：眼睛先扫小标题，再决定读不读正文。小标题**控制 6 字内**，
同类条目要么都有小标题、要么都没有，别一半有一半没有。

### 最该记住的数字用 `stats` 抬成面板

一页里最该被记住的那 2-4 个数字，单独占一页 `stats`：`value` 写 `18.2 万辆` 这种一眼可读的
短值，`label` 写口径（`9 月新能源车销量（同比 +13.6%）`）。

**做不到的**：`columns` 只能左右各放一列要点，**没有**"左边要点 + 右边数字面板"这种混排版式，
也没有"数据看点"那种带框的面板。要点和数字都想要，就**拆成两页**：一页 `content` 讲要点、
一页 `stats` 给数字 —— 别指望一页塞下。

## 交付前自检（逐条过一遍）

0. **视觉检查做过了**：能渲染 = `render_ppt` 的页图逐页对照过（同一份没改过的不重复渲）；
   不能渲染、或页图没附上来 = 逐页文字核过，**并在交付话里写明"未做视觉检查"**。不是"应该没问题"。
1. 封面：`title` 与用户要的主题一致，`subtitle` 没写错单位/日期。
2. 每页都有 `title`，且每页只讲一件事；没有"标题 + 一句空话"的半空页。
3. `bullets` 每条都能一眼读完（≈25 字内），没有从文档里整段复制的长句。
4. 表格列数与表头对齐、数字口径一致（单位写在表头）；**没有 `—` / `待定` 这类占位值**
   （拿不到就补上或删掉那一项）。
5. 章节顺序：开场 → 章节页 → 要点 → 结论/下一步，结尾页在最后，**结尾页有内容不是"谢谢观看"**。
6. 模板与场合匹配（正式汇报别用"暖橙"）。
7. 生成后回执里有实际页数与模板名；页数明显少于你规划的页数，说明有页面被跳过（多半是那页没给可渲染字段），补字段重试。
8. 功能位齐全：有章节分隔（长汇报没有 `section` 就没有呼吸点），结尾页在最后，目录只出现一次。
9. 没有连续两页同一种版式；每页都有文字以外的元素（数字卡 / 表格 / 分栏 / 引言）。
10. **事实性内容逐条有来源**（括注机构名），封面或结尾有总来源行；查不到出处的说法已删掉或标了存疑。
11. **没有任何"放哪儿都成立"的套话页**；页数不够是用内容补的，不是用套话凑的。
12. **用户提过"必须 N 页""第 3 页必须有这句话"这类点数得出来的要求：写进 `expect`**（`pages` /
    `contains: [{ page, text }]`，页数含封面，也含你自己写的结尾页），别自己数、也别等人眼——回执会逐条报断言
    结果，没过就先改再交付。**改完之后也用同一份 `expect` 写进 `edit_ppt`**（"这一页真的改成了"就靠它证明）。

## 交付

产出物落在当前会话工作区。**用 `deliver_file` 交付**（对话里出现可预览的文件卡），不要只报路径；要放到子目录就在 `path` 里写相对子路径（如 `演示/年度规划.pptx`）。

**交付的是那份 .pptx 本身，不是自检的副产品**：页图目录（`*_页图/`）、校验记录、临时脚本都留在工作区里
（它们是你核过版的证据，用户要看你也可以给路径），但**不要把中间产物一起交付出去** —— 用户要的是一个文件。

**版式没看过就说没看过**：渲染不可用 / 页图没附上来时，交付话里写「只做了结构与内容校验，未做视觉检查」，
不要用"应该没问题"糊过去；也不要声称跨端的 PowerPoint / Keynote 长得一模一样（那是我们没验证过的事）。
