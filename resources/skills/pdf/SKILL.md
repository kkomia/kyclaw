# pdf：用 `create_pdf` / `create_report` 出成品文档

## 先选工具

| 用户要什么                                | 用哪个          |
| ----------------------------------------- | --------------- |
| PDF 文件（打印、外发、归档、盖章前定稿）  | `create_pdf`    |
| 屏幕上看/浏览/复制内容，或要能再改的 HTML | `create_report` |

两者**正文写法完全一样**（同一套模板与样式）；`create_report` 落 `.html`，`create_pdf` 走本机 Electron 排版导出 A4 PDF（带背景色、留白边距）。

## 读别人给的 PDF：直接 `read`，抽不出文字时别硬试

- `read` 一条调用就读 `.pdf`：本机抽**文字层**，正文带 `【第 N 页】` 标记。**不要**先用 bash 里的
  `pdftotext` / Python 之类转一遍再读，也不必把 PDF 转成别的格式。
- **扫描件抽不出文字**（`read` 会明说"没有文字层"）：本部署**没有**"PDF → 图片"的通路
  （`render_ppt` 只吃 `.pptx`），所以这份 PDF 的内容**就是读不到**。这时：
  1. **不要**反复重试、不要换写法、不要装渲染器或依赖、不要为此换模型；
  2. 请用户把要问的那几页**截图或导出成图片**（PNG / JPEG），再 `read` 那张图 —— 图片 `read` 能直接看；
  3. 回答/交付时如实说"这份 PDF 是扫描件，我没读到内容"，不要凭文件名推测里面写了什么。
- 上限：单份 ≤64MB、最多抽到第 200 页、正文 ≤64000 字符（超了回执里会写"后面的内容不在这里"，
  别把它当全文）。要读中间某一段用 `offset` / `limit` 按行取窗口。
- 读**图片**会把图片字节发给模型端点（一条出站面）：非「完全访问」的工作区里会先弹一次审批卡；
  用户不批就停下如实说，别换条路偷偷读。

## 一次调用的形状

```
create_pdf({
  title: "2026 年第一季度复盘",     // 可选（缺省写「报告」）；也用它派生文件名
  html: `                         // 必填，正文 HTML **片段**，≤200000 字符
    <h2>一、结论</h2>
    <p>本季度营收 <strong>同比 +18%</strong>，主要来自……</p>
    <h2>二、数据</h2>
    <table><thead><tr><th>项目</th><th>去年</th><th>今年</th></tr></thead>
      <tbody><tr><td>营收</td><td>1.2 亿</td><td>1.4 亿</td></tr></tbody></table>
    <h2>三、下一步</h2>
    <ul><li>把渠道预算从 A 挪到 B</li><li>4 月上线新漏斗</li></ul>
  `,
  path: "报告/一季度复盘.pdf"       // 可选：不给就按标题派生
})
```

回执形如：`已创建 …/报告/一季度复盘.pdf（186221 字节，PDF）`。

## 成品文档的排版口径

`create_pdf` / `create_report` 的样式是**模板固定的**：一级标题、正文、表格边框、隔行底色、分节间距都已经定好。
所以这一节讲的不是"怎么调样式"——**你调不了，也不该调**——而是"在给定样式下，内容怎么组织才像成品"。

> **可选口味（默认打法）**：这一节讲"怎么做才像成品"（配色纪律、留白与节奏、层次的做法）是
> **默认打法**，不是硬口径 —— **用户明确要求别的风格时以用户为准**（用户要蓝色强调色、要密一点、
> 就要一个纯表格页，都按用户说的来）。本节里这几条**不是口味**，任何风格下都得守：
> **不写 `<style>` / 内联样式去覆盖模板**、**表格要有 `<thead>` 且单位进表头**、**缺值不许写占位**。

### 一条底线

每个排版决定都要**从这份文档的内容与用途出发**。"深色 + 金色"不等于专业，"衬线 + 米色"不等于高级；
按内容挑结构，永远比套一个"看起来安全"的样子好。

### 强调色只出现一次一套

- 模板只有**一个强调色**（用在分节线、表头底色、引用框）。**别再叠加第二套配色**：不要自己写内联
  `style="color:#8b5cf6"`、不要给正文加底色、不要做渐变（紫渐变是最典型的"一看就是 AI 生成"）。
- 强调色**不要用在正文文字上**：它出现在分节线、表头、引用框就够，正文保持深色。
- 默认不要用蓝色系强调——蓝是 AI 生成文档里最被用滥的一种。

### 层次靠标签，不靠样式

- 层级只用 `<h2>` / `<h3>` / `<h4>` 表达（模板已给它们定好字号与间距）。**不要用加粗小段落冒充标题**。
- 正文 `<p>` 一句一事；一段超过 5 行就该拆，或提前面加一个 `<h3>`。
- 每节标题下**先给结论/要点，再展开论据**——读者扫标题就能拿到结论。

### 留白与节奏

- 不要把版面填满：正文与表格之间、章节之间靠模板的间距，你别用 `<br>` 硬挤。
- 不要连续堆三段以上没有小标题的正文；长文档每 1-2 屏就有一个 `<h2>` 或 `<h3>`。
- 表格不超过 15 行就占满一页；更长的表按 `<h2>` 拆成几张，或改走 `create_excel`。

### 一致性

- 全篇同一套结构：结论 → 论据/数据 → 下一步。每节都按同一个顺序写。
- 表格写法统一：都有 `<thead>`，单位写在表头，数字口径一致。
- 一份文档一个主题：不要把"汇报"和"附件"塞进同一份。

## 正文 HTML 怎么写（硬口径）

- **是 HTML 片段，不是 Markdown**：写 `<h2>`、`<p>`、`<ul><li>`、`<table>`，不要写 `##`、`**加粗**`、`- 列表`。
- **不要写外壳**：`<html>` / `<head>` / `<style>` / `<body>` 都不要；模板已经带上样式与页边距。
- **不要重复一级标题**：`title` 已经渲染成页首的大标题（`<h1>`），正文从 `<h2>` 开始。
- 会被套用样式的标签（都好看，优先用它们）：`h2` `h3` `h4`~`h6`、`p`、`ul`/`ol` + `li`（可嵌套）、`table`（`thead`/`th`/`td` 带边框与隔行底色）、`blockquote`、`pre` + `code`、`a`、`hr`、`img`（需 data URL）、`small` 或 `class="muted"`。
- 内容太长：`html` 上限 200000 字符。超了先精简，或拆成"摘要 + 附件"两份。
- 图片不要用远程链接或本地文件路径（导出时取不到）：要图片就贴 data URL，或在正文里说明图片位置由用户自行插入。

## 常见坑

- 用 Markdown 写正文 → 原样印成 `## 一、结论`，很难看。
- 自己写了 `<style>` 或内联深色主题 → 打印时可能被浏览器/PDF 忽略底色；样式已内置，别叠第二套。
- 正文又从 `<h1>` 开始 → 与页首标题重复，看起来像两份文档。
- 表格没有 `<thead>` → 表头不加粗、跨页时也不会重复。
- 一大张没有分节的表 → PDF 会在页中切开；按 `<h2>` 分节，或把大表拆成几张。
- 空白/极短的正文 → 生成的成品没有信息量，宁可多写一段结论与下一步。
- 在无窗口环境（纯 Node 测试）里 `create_pdf` 会报"PDF 导出不可用…"——这是环境限制，不是用法错误：**改用 `create_report`** 出 HTML，或让用户在桌面端应用里重试。
- 用紫色渐变或"深蓝 + 金色"当强调色 → 一眼就是模板味；强调色由模板给，别再叠第二套。
- 强调色用在正文文字上 → 可读性直接掉；它只该出现在分节线、表头、引用框。

## 自检分档：**不做**视觉检查（如实声明）

PDF / HTML 走的是"HTML → 模板排版"，本部署**没有** PDF → 图片的通路（`render_ppt` 只吃 `.pptx`），
所以这一档的自检就是**结构 + 内容校验**，交付时**写明"未做视觉检查"**：

- **不做的事**：找 `soffice` / `pdftoppm` 之类把 PDF 转成图来看、装渲染器、为此换模型。
- **要做的**：把下面「交付前自检」逐条核一遍 —— 正文是 HTML 片段、层级不跳、表格列数对齐、
  数字自洽、篇幅与用途匹配。用户能在右侧工作台直接预览这份 PDF（**你自己看不到**），
  就更要把能查的都查掉。
- **结构自检通过 ≠ 排版没问题**：导出成功、回执里没报错，只说明**生成成功**；文字有没有被页边
  切开、表格有没有跨页错行，这些**没看过就不评**，不要说"打印出来应该没问题"。

## 交付前自检

0. **PDF 看不到成品**（没有 PDF → 图片的通路），所以交付前**必须**把下面各条逐条核一遍，
   不能因为"看不到"就跳过；交付话里写清"未做视觉检查"。
1. 正文是 HTML 片段：没有 `<html>`/`<head>`/`<style>` 外壳，没有从 `<h1>` 开始。
2. 结构齐全：结论在前 → 论据/数据 → 下一步；`<h2>` 分节，层级不跳。
3. 表格：有 `<thead>` + `<th>`，每行单元格数与表头一致，单位写进表头；**没有 `—` / `待定` 这类
   占位值**（拿不到就补上或删掉那一行）。
4. 数字与结论一致（正文里提到的数字与表格里的对得上）。
5. 没有远程图片、没有本地文件路径引用。
6. 篇幅与用途匹配：汇报 1-3 页、复盘 3-8 页；超出就拆文档。
7. 回执里有路径与字节数；PDF 那件还带结构自检结论（末尾没有报错就是通过了）。
8. 全篇只有模板那一套强调色：没有内联颜色、没有渐变、没有自加底色。
9. 没有连续三大段无小标题的正文；每节标题下先给结论。
10. **事实性内容逐条带来源**（机关/机构/媒体名，需要时补日期）；查不到出处的要么删掉、要么写明存疑。
11. **没有"放哪儿都成立"的空话段落**；篇幅不够用实质内容补，不许用套话凑。

## 交付

产出物落在当前会话工作区。**用 `deliver_file` 交付**（对话里出现可预览的文件卡，PDF 能在右侧工作台直接看），不要只报路径。

**交付的是那份 PDF / HTML 本身**：临时脚本、校验记录这类中间产物留在工作区里，不要一起交付出去。
**版式没看过就说没看过**：交付话里写明「只做了结构与内容校验，未做视觉检查」。
