# docx：用 `create_docx` 做 Word 文档

## 什么时候用我

- 用户要一份**别人会打开、会改、会盖章**的文档：合同/协议、制度办法、项目方案、说明书、通知、纪要。
- 用户明确说 `.docx` / Word / "能编辑的文档"。

不要用我：投屏演示（→ `pptx`）、纯数据表（→ `xlsx`）、只读/打印/外发的成品（→ `pdf`）。

## 读别人给的 Word：`read` 一条调用

- `read` 读 `.docx` 回的是 **markdown**：标题、列表、表格都在；内嵌图片只留一句"（图片已省略）"
  占位（抽不动图）。**不要**自己解 zip、"转成文本"再读。
- **旧版 `.doc`（二进制）也能读**：`read` 会用随包 LibreOffice 把它转成 `.docx` 再抽（原件不会被改动，
  转换在临时目录做）。转换器缺失/文件加密/损坏时它会明说原因 —— 那时再让用户在 Office 里另存为
  `.docx` 重试，或把要看的页面**截图/导出成图片**（图片 `read` 能直接看）。
- **别的办公格式也归 `read`**：`.xlsx` / `.csv` 回表格（带行列号），`.pptx` 回逐页文字（按真实页序，
  图片/图表只说"没读"）；做 PPT 的页图自检仍用 `render_ppt`。别再让用户"导出 CSV 再读"。
- 上限：单份 ≤32MB、正文 ≤64000 字符（办公格式的截断切在行/页边界上，回执会说清"读到哪、
  还有多少没读"）；读中间某一段用 `offset` / `limit` 按行取窗口。
- **读回来的是文字结构，不是版式**：要评版式/看内嵌图，让用户导出一份 PDF 或截图，
  或明确告诉用户"排版我没看到"。

## 一次调用的形状

```
create_docx({
  title: "设备采购管理办法",        // 写成 Word 的 Title 段（导航窗格能认）
  blocks: [                        // 按顺序排；1-1000 块
    { type: "heading", text: "第一章 总则", level: 1 },
    { type: "paragraph", text: "为规范采购流程，制定本办法。" },
    { type: "bullets", items: ["预算内采购由部门审批", "超预算报总经理审批"] },
    { type: "table", headers: ["金额区间", "审批人"], rows: [["≤1 万", "部门经理"], ["＞1 万", "总经理"]] },
    { type: "heading", text: "第二章 流程", level: 1 },
    { type: "paragraph", text: "……" }
  ],
  path: "文档/采购管理办法.docx"    // 可选：不给就按 title 派生文件名
})
```

回执形如：`已创建 …/文档/采购管理办法.docx（12844 字节，14 个内容块）`。

## 改的时候：`edit_docx`（只发改动，不发整份）

**第一版用 `create_docx`；只要不是"重做"，改动一律走 `edit_docx`** —— 它只收"改哪一块 + 改成什么"，
其余块从会话里记着的源结构读，不必再发一遍（钱花在模型输出上：发一个 op 与重发整份 `blocks`
是两种量级的开销）。

```
edit_docx({
  path: "文档/采购管理办法.docx",     // 必填：create_docx 回执里那个路径
  ops: [
    { op: "replace", block: 2, content: { type: "paragraph", text: "为规范采购流程，制定本办法（2026 修订）。" } },  // 换掉第 2 块
    { op: "insert",  after: 4, content: { type: "heading", text: "第三章 验收", level: 1 } },                      // 第 4 块后插一块
    { op: "delete",  block: 7 },                                                                                  // 删掉第 7 块
    { op: "meta",    title: "设备采购管理办法（修订版）" }                                                          // 改标题（空串 = 去掉标题）
  ]
})
```

- **块号是"内容块"的块号**（1 起、按 create_docx 的 `blocks` 顺序）：`blocks[0]` 是第 1 块，
  **标题不算一块**（它是独立的 Title 段）。`replace` / `delete` 给 1..N，`insert` 的 `after` 给 0..N
  （`after: 0` = 插到第一个内容块之前）。
- **一个 `bullets` 是一个块、一张 `table` 是一个块**：`{ type: "bullets", items: [...] }` 在文档里
  是好几行，但块号只有 1 个 —— 删它就是把那一组要点整段删掉。
- `ops` 按顺序应用，每一步都按**当前**块序算（"在第 2 块之后插一块"之后再"删第 3 块"，删掉的正是
  刚插进来的那一块）。
- 回执与 `create_docx` 同形，末尾多一段**改后块序**（`标题〈…〉；块序（1 起，不含标题）：1 小节〈…〉｜2 段落〈…〉…`）
  —— 就用它核"用户说的第 2 块"是哪一块，别为此再把整篇读一遍（每块文字在回执里截断到 16 字）。
- 盘上那份**被手动改过或删掉了**时它不会动手：回执给出 `ifChanged` 的出口 ——
  `overwrite`（以会话里记的源为准覆盖，文件里的手改会丢）/ `stop`（默认：什么都不做）。
  **`adopt`（读文件里的旧内容重建源）在 Word 这边不支持**：Word 的文字与版式不是一一对应，
  读回来重建会丢版式、图片与批注 —— 那种情况用 `create_docx` 按新内容重做一份。
- 改完**也用 `expect` 核一遍**（"这一段真的改成了"就靠它证明）：与 create 同一把尺子，
  按正文部件（`word/document.xml`）核，页眉页脚与批注不算。
- 改完的**源结构与指纹会跟着更新**，所以可以连着改好几次（每次都只发改动）。
  源结构超过 2MB 的文档记不下：`create_docx` 会在回执里明说"源结构未登记，edit_docx 不可用"，
  那种文档只能整份重发。

## 四种块（`blocks[].type`）

| 块          | 字段                                             | 用途                                                 |
| ----------- | ------------------------------------------------ | ---------------------------------------------------- |
| `heading`   | `text`、`level` 1-6（缺省 1）                    | 章节标题；**层级要真按文档结构走**（1 = 章，2 = 节） |
| `paragraph` | `text`                                           | 一段正文（空串会被跳过）                             |
| `bullets`   | `items[]`                                        | 项目符号列表（每条一个圆点）                         |
| `table`     | `headers?`（可选，加了会加粗成首行）、`rows[][]` | 表格，占满页宽                                       |

只支持这四种。要的东西表达不出来时，用 `paragraph` 说清楚，别指望 Markdown 语法被解析——`**加粗**`、`##`、`- ` 这些会**原样当文字**印出来。

## 中文正式文档的排版口径

我们的工具**不暴露字号 / 字体 / 缩进**——标题层级与正文样式由渲染器统一决定。所以下面这些值不是让你去设，
是让你**在内容层面做对**（该用几级标题、编号怎么写、表格里放什么），别用 Markdown 或全角空格去"手工排版"。

> **可选口味（默认打法）**：这一节里讲"做成什么样"的判断（下面「字号与层级」整节、首行缩进惯例、
> 强调方式）只是**默认打法**，不是硬口径 —— **用户明确要求别的风格时以用户为准**（用户说"都要居中"
> "字大点""别分级了"就照做，不要拿本节去驳回）。本节里这几条**不是口味**，任何风格下都得守：
> **全角标点**、**编号要自己写进文本**、**表格必须给 `headers`**、**缺值不许写占位**。

### 字号与层级（判断层级用，不是参数）

| 中文字号 | pt   | 通常用在哪         |
| -------- | ---- | ------------------ |
| 二号     | 22   | 公文标题           |
| 三号     | 16   | 公文的章标题与正文 |
| 四号     | 14   | 小节标题           |
| 小四     | 12   | 一般正文           |
| 五号     | 10.5 | 表格内文字、注释   |

层级靠 `heading` + `level` 表达，不靠字号；相邻两级之间要能一眼分辨（正文与标题的字号差通常在 1.5 倍以上）。

### 正文与标点

- 中文正文用**全角标点**（，。；：（）「」），数字与英文词用半角；中西文之间不要手工塞空格。
- 首行缩进 2 字符是中文正文惯例，但**不要用两个全角空格去模拟**（复制、导出都会串行）。要视觉分层就用 `heading` 分节。
- 中文**没有真斜体**：强调用加粗（给 `bullets` 或独立 `paragraph`）而不是斜体。
- 数字口径全篇统一：`1,234` 与 `1234` 不要混用；金额在表头或句子里写明单位。

### 标题编号体系（公文 / 制度惯例）

| 层级 | 写法     | 落到哪               |
| ---- | -------- | -------------------- |
| 一级 | `一、`   | `heading` `level: 1` |
| 二级 | `（一）` | `heading` `level: 2` |
| 三级 | `1.`     | `heading` `level: 3` |
| 四级 | `（1）`  | 用 `paragraph` 起句  |

**编号要自己写进 `heading.text` / `paragraph.text`**（工具不会替你加序号）。一份文档只用这一套编号，不要一、（一）、1. 混排。

### 公文体（GB/T 9704 口径）的结构

用户说"写份通知 / 请示 / 报告 / 函"（公文）时，按这个顺序落块：

1. `heading` `level: 1` —— 标题（发文机关 + 事由 + 文种）
2. `paragraph` —— 主送机关（顶格，后接全角冒号）
3. 正文 —— `paragraph` 逐段；一级小标题用 `heading` `level: 2`（`一、`）
4. `paragraph` —— 附件说明（如有）
5. `paragraph` × 2 —— 发文机关署名、成文日期
6. `paragraph` —— 抄送（如有）

**不要**在正文里手工画"红头""分隔线"：`create_docx` 不支持图形与边框，写出来只会变成一串怪字符。

### 表格

- 中文正式文档惯用**三线表**（表头一条线、末行一条线）。我们的 `table` 只支持表头加粗、画不了三线，所以**表头必须给 `headers`**，否则读者分不清表头与数据。
- 单元格只放对得齐的短值；长说明放正文段落。列数在整张表里一致。

## 长度上界（超了整次调用会失败）

| 位置                              | 上界                                           |
| --------------------------------- | ---------------------------------------------- |
| `blocks`                          | 1000 块                                        |
| 单块 `heading` / `paragraph` 文字 | 20000 字                                       |
| `bullets.items`                   | 200 条，每条 2000 字                           |
| `table.rows`                      | 1–2000 行（至少要有一行数据）                  |
| `title`                           | 建议 60 字内（也用它派生文件名，过长会被截断） |

上界很宽，但**一段别写成万字长文**：拆成多段更像正式文档（阅读器、导出 PDF 都更好排）。

## 常见坑

- 用 `paragraph` 当标题：句首加"一、"并不会让它进导航窗格；结构靠 `heading` + `level`。
- `level` 跳级（1 → 4）：导航结构会乱，按 1/2/3 递进。
- 想给某段"加粗/斜体/颜色"：当前工具不支持行内样式，改写成短句或拆成 `bullets`。
- 表格没有 `headers`：首行会被当普通数据行，读者不知道每列是什么。
- 表格单元格里写长段落：单元格不换段，长内容会挤；要长说明就写正文，表格只放对得齐的短值。
- 一份文档里反复出现同一个标题：合并到一处，用层级区分。
- 列表项里带换行：每条 `items[i]` 是一行，要分层就分多组 `bullets`（或改用 `heading` 分节）。
- 用全角空格做首行缩进：排版会串行，导出 PDF 时更明显。缩进交给渲染器，你只管分段。
- 中文用斜体强调：中文没有真斜体，渲染出来是机械倾斜；改用加粗或分点。
- 编号体系混排：同一份文档里同时出现"一、"、"1."、"（一）"会让结构读不出来，统一一套。
- 把"红头""分割线""公章"写成字符画：工具不渲染图形，这些会变成乱码字符，宁可用一句话说明位置。

## 自检分档：版式重要，但本部署没有 Word 的渲染通路

Word 属于"版式重要"的那一档（分页、页码、表格换行都会影响成品观感）。但**本部署没有 docx 的渲染
通路**：`render_ppt` 只吃 `.pptx`，Word 这边没有可用的逐页导出（也不打算为它装一个）。所以这一档
在本机只能做到**结构 + 内容自检**，并在交付时**如实写明"未做视觉检查"**：

- **不做的事**：去找 LibreOffice / `soffice` 把文档转成 PDF 再看图、`npx` 装转换器、换个模型"想想办法"。
  这些我们没测过也不维护，做了只会让这一轮变长变贵。
- **要做的**：把下面「交付前自检」逐条过一遍（每个 `heading` 下面有内容吗、编号体系统一吗、
  来源写了没、落款齐不齐）。**这一遍必须做完**，不能因为看不到成品就跳过。
- **结构自检通过 ≠ 排版没问题**：块数、层级、表格列数对得上，只说明**结构**没问题；段落在纸上的
  换行、分页、字号层级这些**看不到就不评** —— 不要替它下结论，也不要说"版式很好看"。

## 交付前自检

0. **内容层面逐条核过了**（上一条分档那一遍真的做完了），交付话里写清"未做视觉检查"。
1. `title` 与用户要的文件名/主题一致（它会进文件名，也会进文档首行）。
2. 章节层级：`level: 1` 是章、`2` 是节，没有跳级。
3. 每个 `heading` 下面都有内容，没有空章节。
4. 表格：`rows` 每行长度与 `headers` 对齐，数值口径统一（单位写在表头）；**没有 `—` / `待定`
   这类占位值**——拿不到就补上或删掉那一行。
5. 列表项都是短句；没有把整段正文塞进 `bullets`。
6. 结尾有落款/日期/负责人这类用户需要的字段（对方要签字盖章时尤其重要）。
7. 回执里的块数与你传的块数大致对得上（空块会被跳过是正常的）。
8. 中文文档：编号体系只有一套；标点全角；没有用全角空格或斜体硬凑排版。
9. **事实性内容（数字/政策/引述）逐条带来源**（`（财政部）` 这种括注）；查不到出处的要么删掉、
   要么写明存疑。写"网传""据了解"不算来源。
10. **没有"放哪儿都成立"的空话段落**；段落不够就用实质内容补，不许用套话凑篇幅。
11. **用户提过"文档里必须有这句话"：写进 `expect.contains`**（在正文里核，页眉页脚/批注不算）——回执会
    逐条报断言结果，没过就改完再交付。

## 交付

产出物落在当前会话工作区。**用 `deliver_file` 交付**（对话里出现可预览的文件卡），不要只报路径。

**交付的是那份 .docx 本身**：临时脚本、校验记录之类的中间产物留在工作区里，不要一起交付出去。
**版式没看过就说没看过**：交付话里写明「只做了结构与内容校验，未做视觉检查」。
