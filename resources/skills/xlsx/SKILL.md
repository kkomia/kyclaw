# xlsx：用 `create_excel` 做 Excel 工作簿

## 什么时候用我

- 用户要**按行列看的数据**：台账、清单、预算表、对账、统计汇总、导入模板。
- 用户明确说 Excel / `.xlsx` / 表格。

不要用我：叙述性内容（→ `docx`）、要投屏的图表页（→ `pptx`；图表本身当前不支持，先给数据表）、只要看不想改的成品（→ `pdf`）。

## 一次调用的形状

```
create_excel({
  sheets: [                          // 1-50 张，按顺序落进工作簿
    {
      name: "费用明细",              // 工作表名：>31 字或含 []:*?/\ 会被自动归一
      rows: [                        // 二维单元格数组：外层是行，最多 5000 行/表
        ["日期", "项目", "金额", "备注"],       // 第一行当表头（纯文本即可，工具不会特殊处理）
        ["2026-01-05", "服务器", 62000, ""],
        ["2026-01-12", "域名", 480, null]      // null = 空单元格
      ]
    },
    { name: "汇总", rows: [["合计", 62480]] }
  ],
  title: "2026 年 1 月费用",        // 可选：不给 path 时用它派生文件名；再不给就用第一张工作表名
  path: "表格/费用明细.xlsx"         // 可选
})
```

回执形如：`已创建 …/表格/费用明细.xlsx（9123 字节，2 张工作表／5 行）`。

## 单元格口径（关键）

- 允许的值：**字符串 / 数字 / 布尔 / null**（null = 空单元格）。
- **数字写数字**：`62000` 不要写成 `"62000"`，否则 Excel 里它是文本（右对齐不了、算不了和）。
- **字符串原样**：`"2026-01-05"` 保持字符串（不猜成日期类型），日期想被 Excel 识别就写 `2026-01-05` 这种标准格式，用户选中后自行设格式。
- **不支持公式**：`"=SUM(B2:B9)"` 会**原样写成文本**（Excel 打开不会计算）。要汇总就**自己先算好**，把结果写进单元格（可以在 `备注` 里写"合计"）。
- **单元格字符串上限 32767 字符**（Excel 硬限制），超了文件会坏；长文本请换行拆分或改用 docx。
- 每张表 ≤5000 行、≤50 张表。

## 工作表名

- 非法字符 `[]:*?/\` 与超过 31 字符会被自动归一（替换/截断）。
- 重名会自动加序号后缀（`Sheet`、`Sheet-2`），不会整份失败。
- 建议用业务名（"费用明细"、"汇总"）而不是默认的"Sheet1"，用户打开就能看懂。

## 表的结构与数字口径

> **可选口味（默认打法）**：这一节里只有「假设与结果分开」是**默认打法**（一种组织方式的建议）——
> **用户明确要求别的组织方式时以用户为准**。其余各条（数字写数字、单位进表头、零与空不同义、
> 行序与合计的位置）是**硬口径**：它们决定这张表能不能算、读得对不对，不是好不好看。

### 行类型（读者靠它读懂这张表）

| 行类型      | 怎么放                               | 例                                 |
| ----------- | ------------------------------------ | ---------------------------------- |
| 表头行      | `rows[0]`，列名写全、带单位          | `["月份", "收入（万元）", "同比"]` |
| 分类行      | 第一列写分类名，其余用 `null` 占位   | `["一、主营业务", null, null]`     |
| 明细行      | 正常数据                             | `["1 月", 128, "12.4%"]`           |
| 小计 / 合计 | 紧跟它汇总的明细之后，或整表最后一行 | `["合计", 1536, ""]`               |
| 空行        | 只用来分区，别滥用                   | `[null, null, null]`               |

一张表只用一套行序：表头 → 明细 → 合计。**"合计"别插在明细中间**（排序、筛选、透视都会乱）。

### 数值口径（工具不写公式，所以这一层格外重要）

- **数字列写数字**：`62000` 不要写成 `"62000"`。
- **年份写数字**：`2024`；写成 `"2,024"` 这类带千分位的字符串会被 Excel 当文本。
- **比率**：本工具不设百分比格式，写 `0.08` 在 Excel 里就显示 `0.08` 而不是 `8%`。要一眼可读就
  **写字符串 `"8.0%"`**，并在表头注明该列是百分比；同一列不要一半 `0.08`、一半 `"8.0%"`。
- **小数位全列一致**：要么都是 `128.00`、要么都是 `128`；混着写看起来像没对齐。
- **负数择一**：`(1,234)` 或 `-1234`，全表统一。
- **零与空不同义**：真是 0 就写 `0`；"没有这个数据"写 `null`。
- **单位进表头**：`金额（万元）`，不要在单元格里重复写"万元"。

### 假设与结果分开

预算、测算这类表，把**用户可调的输入**和**算出来的结果**分成两张工作表（如 `假设` / `汇总`）。
因为工具不写公式，读者点开单元格也看不到依赖关系——分区是他们唯一能看出"哪个数可以改"的线索。

## 常见坑

- 表头写成 `"合计"` 之类的汇总行混在数据里：把它放到最后一行或用单独一张"汇总"表，别插在中间。
- 每行列数不一致：不会报错，但表格会缺格；同一列要么都有值，要么用 `null` 占位。
- 金额混单位：`62000` 与 `"6.2 万"` 混在一列，排序和求和就废了；统一成一个数字口径，单位写进表头（"金额（元）"）。
- 一列里混数字与文本数字（`62000` 与 `"62000"`）：Excel 会当两种类型，去重/透视都别扭。
- 把长报告塞进一个单元格：单元格没有换行排版；叙述内容走 docx 或 report。
- 只想给一个"能看的表"却要 5000 行：先确认用户真要这么多；表格大时先给摘要表 + 明细表两张。
- 年份写成 `"2,024"`：Excel 会当文本，排序时排在数字后面。
- 比率写成 `0.08` 却指望显示成 `8%`：工具不设数字格式，写 `0.08` 就是一串小数。

## 自检分档：**跳过**视觉检查（这一档只校数据）

`create_excel` 只写数据，**不写样式** —— 没有字号、颜色、列宽、冻结窗格，也没有图表；产出物就是
一张"行列 + 字面值"的表。所以这一档**没有可看的版式**，视觉检查在这里既不必要也检查不出东西：

- **不做**：不要为了"看一眼"去导出截图、不要找渲染器 / 转换器、不要为此多跑任何工具。
- **要做**：结构与内容校验（下面「交付前自检」那 9 条）—— 数字类型、单位口径、小数位、行序、
  空值语义逐列过一遍。**这一遍是这一档的全部**。
- 交付时说明"这一档只做了数据结构校验"就够了；**不要**声称"表格看起来没问题"（你没看过），
  更不要把"没有样式"当成缺陷来解释（那不是缺陷，是这个工具的口径）。

## 交付前自检

1. 每张表第一行是表头，列数在整张表里一致。
2. 数字列全是数字类型（没有引号包起来的数字、没有"3.2 万"混入）。
3. 汇总/合计是自己算好的具体值，不是公式字符串。
4. 没有超过 32767 字符的单元格；长文本已移出表格。
5. 工作表名与内容对得上，顺序符合阅读习惯（明细在前、汇总在后，或反之但要说清）。
6. 空值用 `null` 而不是空字符串占位（空串也是"有值"，会影响计数类判断）。
7. 回执里的工作表数与行数与你传的一致。
8. 行序规范：表头 → 明细 → 合计；"合计"没有插在明细中间。
9. 数字口径逐列检查过：年份是数字、比率同一列写法一致、小数位一致、负数写法一致。
10. **用户提过"必须 N 张表""表里必须有这几个字"：写进 `expect`**（`sheets` / `contains`）——文本断言按
    **整本工作簿**的单元格文字核（不分工作表），回执会逐条报结果，没过就改完再交付。
